# REQUESTS — реестр предложений по коду

Зачем этот файл. За вечер по Quote Guard пришло три предложения от внешнего
аудитора, и одно из них (heredoc) оказалось настоящей дырой, а два — scope creep.
Без записи через неделю никто не вспомнит, что именно предлагали и почему
отклонили, и отклонённое вернётся как «а почему не сделано».

Правило то же, что у канона чисел: **в код попадает только то, что закрывает
верифицированный отказ.** Предложение не становится требованием от того, что
оно прозвучало. Но и отклонение должно быть проверяемым, а не вкусовым.

## RQ-001 — разбиение по операторам

**Проверка.** `echo "a && b"` в текущем лексере — `safe=True`. Наивное разбиение
по `&&` до лексинга даёт два фрагмента: `echo "a ` и ` b"` — оба «несбалансированы»,
то есть валидная команда будет заблокирована.

**Статус:** ОТКЛОНЕНО.

**Обоснование.** Для проверки парности разбиение не даёт ничего: состояние
кавычек глобально, а разрезание по операторам, найденным в состоянии NORMAL,
эквивалентно одному проходу. Реализация «split до лексинга» (как сформулировано
в запросе) ломает валидные команды — ровно тот false positive, ради устранения
которого проект существует.

**Тест:** не добавлен. Если разбиение когда-нибудь понадобится для политик
(а не для парности), оно должно быть post-lex и с отдельным набором кейсов.

## RQ-002 — heredoc

**Проверка.** До правки: `cat >> f.txt <<EOF ... EOF` + `echo "broken` → хук
отдавал exit 0. Это fail-open: незакрытая кавычка после разделителя реально
вешает шелл. При этом сам лексер на теле heredoc с одной кавычкой давал
`safe=False` — то есть без пропуска был бы false positive.

**Статус:** ПРИНЯТО.

**Обоснование.** Реальное зависание, а не косметика. Решение — не пропуск и не
наивный лексер, а маска: тела заменяются пробелами с сохранением длины, поэтому
смещения в отчётах остаются верными, а хвост после разделителя проверяется.
Незакрытый heredoc (`cat <<EOF` без `EOF`) тоже зависание и теперь блокируется
с `state=HEREDOC`.

**Тест:** `tests/fixtures/cases.jsonl:12-14` (тело с непарной кавычкой — пропуск;
хвост после разделителя — блок; нет разделителя — блок); `tests/test_hook.py:73-82`
(два кейса heredoc и два here-string, плюс изменённое ожидание старого кейса
с «пропускается» на «блокируется»).

## RQ-003 — детект разрушительных команд

**Проверка.** `echo "hello" && rm -rf /` проходит через хук — и это by design:
контракт хука «повесит ли это шелл», а не «разрушительно ли это».

**Статус:** ОТКЛОНЕНО.

**Обоснование.** Другой продукт. У списка опасных команд нет естественной
границы (`rm -rf`, `mkfs`, `dd`, `:(){ :|:& };:`, `chmod -R 000 /`), и пара
паттернов в quote guard даёт не защиту, а ощущение защиты — то есть хуже, чем
отсутствие проверки. Если такой слой нужен, он делается отдельно, со своим
списком правил, своим конфигом и своими тестами.

**Тест:** не добавлен.

## RQ-004 — порт маски heredoc в JS

**Проверка.** После RQ-002 Python пропускал легитимный `cat <<EOF` со скриптом,
а `parity_check.js` — нет: в JS-реализации heredoc не обрабатывался вообще.
Две реализации расходились, хотя `tests/test_parity.js` существует ровно для
того, чтобы такого не было.

**Статус:** ПРИНЯТО.

**Обоснование.** Проект заявляет побайтовый изоморфизм логики двух реализаций.
Разошедшееся поведение делает это заявление ложным.

**Класс против экземпляра.** Это фикс **экземпляра**: heredoc не был портирован.
**Класс** — «у каждого набора своя таблица кейсов, поэтому реализации могут
разойтись при зелёных тестах» — закрыт отдельно, в RQ-005.

**Тест:** те же 5 кейсов добавлены в `tests/test_parity.js`; счёт вырос
до 44 проверок / 29 случаев.

## RQ-005 — общий фикстур вместо двух таблиц

**Проверка.** До правки: Python тестировал 31 грамматический случай, Node — 29.
Два случая проверялись только в Python — экранированные кавычки вне контекста
и путь с пробелами в powershell. То есть изоморфизм для них не был верифицирован,
он просто не тестировался. Асимметрия существовала всё время и была невидима,
потому что таблицы у наборов свои.

**Статус:** ПРИНЯТО.

**Обоснование.** Порт (RQ-004) закрыл один экземпляр. Класс закрывается только
общим источником кейсов: `tests/fixtures/cases.jsonl`, один JSON на строку
(`shell`, `cmd`, `safe`, `why`). Оба раннера читают его и прогоняют. Расхождение
теперь невозможно по построению: добавить кейс можно только в общий файл, и
оба набора его увидят.

**Тест:** оба набора печатают одно и то же — 46 проверок / 31 грамматический
случай. Совпадение счётчиков и есть проверка симметрии: если кто-то вернёт
отдельную таблицу, числа разойдутся и это будет видно в выводе.

## Как добавлять запись

1. Сначала проверка: команда, которую предложение ломает или чинит, и что
   показывает текущий код. Без воспроизведения запрос не рассматривается.
2. Статус: ПРИНЯТО / ОТКЛОНЕНО / ОТЛОЖЕНО.
3. Обоснование — почему, а не «не нравится».
4. Если ПРИНЯТО — какие тесты закрывают, и обновились ли счётчики в
   `CANONICAL_NUMBERS.py` (он печатает их прогоном, а не из текста).
