# Проверочный набор: 1416 проб в 261 КБ

Зачем. Сырые архивы прогонов — 569 МБ, и в статье они «available from the author
on request». Читатель не может ничего проверить, пока не напишет автору. Этот
набор снимает вопрос: он содержит только поля, нужные для арифметики, и
воспроизводит все числа статьи.

## Состав

| Файл | Что |
|---|---|
| `probes.jsonl` | 1416 строк: `series, probe_id, arm, n, k, answer_val, expected_val, thinking_present, format_ok, tool_used` — 261 КБ |
| `build_bundle.py` | собирает `probes.jsonl` из `Argon_v*/runs/*/archive.jsonl` |
| `verify_numbers.py` | пересчитывает ключевые числа статьи из `probes.jsonl`, без зависимостей |

Чего в наборе нет: промптов, полных ответов, `thinking`, таймингов, хэшей.
Только то, что нужно для долей, интервалов и критериев.

## Запуск

```bash
python verify_numbers.py
```

Вывод (сверено с `CANONICAL_NUMBERS.txt`):

```

v15: exact 62, overshoot 23, undershoot 10, unparsed 1, glitch 0
     сумма 96, дрейф 33 = 34.4%
v9: с thinking 173/240 = 72.1% верно (ошибок 27.9%); без thinking 3/48 = 6.2% (ошибок 93.8%)
No-Tools: 960 проб, tool_used 0/960
v11 n=16 формат: A 48/48, B 43/48
v11 n=16 точно: A 22/48 = 45.8%, B 28/48 = 58.3%
```

## Схемы серий различаются

v6 писал `answer_value` / `answer_ok` / `dose` вместо `answer_val` / `format_ok` /
`n`; `build_bundle.py` нормализует имена, отсутствующее поле остаётся `null` —
это тоже информация, а не пропуск.

## Если набор примут

В статье Data Availability меняется одна строка: вместо «available from the
author on request» — ссылка на этот набор и на `verify_numbers.py`. Тогда
утверждение проверяемо без переписки с автором, а сырые 569 МБ остаются
доступны по запросу как расширение, а не как единственный путь.
